## 01 目的とKGI

本リニューアルの目的は見た目の刷新ではなく、**CV（特に資料DL）が構造的に生まれるサイトへの再設計**である。トンマナ統一はその手段の一つとして同時に行う。

### 目標

| 指標 | 現状（26年6-8月平均） | 目標 | 備考 |
| --- | --- | --- | --- |
| 月間CV合計 | 約350件 | **375件（+10%）** | 4CVの内訳目標は §08 の計測分離後に設定 |
| 最重要CV | 資料ダウンロード |  | 検討初期〜後期まで受けられる資料ラインナップを拡充（§07） |
| コラム経由CV | **0件** | 新設KPI | 現状最大の構造的損失。§05 T9で対処 |

### 基本方針（優先順位）

1. **コラム→CVの接続** — 流入の過半が着地するコラムからCV導線を張る
2. **商用KWページの新設** — 料金・機能・比較・課題別など「買う気のある人」の受け皿
3. **IA・グロナビ再設計** — 検討プロセスに沿った情報設計
4. **トンマナ統一** — corpサイト（manebi.co.jp/corp/）の世界観に統一。紫単色の旧トンマナは廃止

### 設計原則：流入元別の情報連続性（v1.4追加）

比較サイト・コーポレートサイト・広告LP・検索——**どの流入元から来ても、直前に見ていた情報の続きがサイトで完結する**状態を作る。比較サイト経由の検討者は各社を見比べた上で指名で戻ってくるため（比較サイト経由リードはアイミツ68・ITトレンド30・BOXIL28・ミツモア29／3ヶ月＝kintone実測）、**比較サイトに載せている料金・スペック情報と同等以上を本体サイトでも公開し、情報の非対称を解消する**。流入元→期待情報→受けページの対応は §04 のマップに定義。

### 設計原則：「4つの不」への回答としてのサイト

既存の営業フレームワーク「4つの不」をサイト全体の設計原則に採用する。**不信**（この会社は信頼できる？→実績・事例・受講者の声・セキュリティ）／**不要**（本当に必要？→定量・定性メリット）／**不適**（自社にベスト？→比較表・業界別ページ）／**不急**（今やるべき？→放置リスク・法改正/施行日訴求）。各ページがどの「不」に答えるかを §05 で明記する。

## 02 現状分析（データ）

GA4（property 442056267）・Search Console・SEO対策KW管理シートの実データに基づく。期間は主に2026年6〜8月。

### ボトルネック①：コラム流入がCVゼロ

| ランディング | セッション | CV | CVR | 直帰率 |
| --- | --- | --- | --- | --- |
| TOP `/` | 9,517 | 218 | 2.3% | 42% |
| 広告LP `/std_03h` | 8,212 | 123 | 1.5% | 59% |
| コラム上位10記事 合計 | 約20,000 | **0** | **0%** | 88〜94% |
| `/service/e-learning` | 1,772 | 69 | **3.9%** | 38% |
| `/contact`（直接流入） | 577 | 113 | 19.6% | 53% |

サイトの非指名流入の大半を稼ぐコラムが、CVに1件も接続していない。**ここが本リニューアル最大の改善余地**。なお /service/e-learning はCVR 3.9%と最良で、「サービスを理解した人は転換する」ことの証左。問題は理解に至る動線が無いこと。

### ボトルネック②：商用KWの受け皿不在・順位崩落

- クリック上位クエリは「パワハラ 定義」「スローガン例」等の**情報クエリと指名のみ**。商用KWは上位にほぼ皆無
- ビッグKW「e ラーニング」（月間検索74,000）は表示LPが /service/e-learning/ だが**順位がほぼ付いたことがない**。対策34KWのうち約半数が全期間圏外
- 商用KWの受け皿が**コラム記事に集中**（t-033・t-014・t-059・t-063）。「eラーニング おすすめ」は26年7/1に1位到達後、7/8以降圏外。t-033/t-014系のKW群が7月上旬を境にまとまって下落
- サイト全体セッションも減少傾向：23,348（25年10月）→ 16,630（26年7月）。情報系クエリ（スローガン例・研修 感想等）の減衰が主因で、**非商用トラフィック依存が崩れつつある**
- 「パワハラとは」は表示8.6万回・9位・CTR 0.3% — Title/構成改善だけで拾える余地大

### その他の事実

- 「manebi ログイン」系クエリで3ヶ月に約960クリック — **受講者がサービスサイトへ大量流入**。ナビに受講者導線が必要（§04）
- GA4キーイベントが `CV_資料DLor問合せor体験` の1本のみで、CV種別の効果検証が不可能（§08で是正）
- 月6記事のリライト運用（15位→8位が最コスパ等の基準）が既に存在。§06でこの運用を仕組み化する

## 03 競合・参考サイト分析

競合5社（インソース／Schoo／AirCourse／learningBOX／Smart Boarding）と参考B2Bサイト5社（カオナビ／SmartHR／タレントパレット／セールスマーカー／Loglass）を実査（2026-09-01）。

### manebiが競合より弱い部分（優先度順）

|  | 弱点 | 競合の状況 |
| --- | --- | --- |
| P1 | **料金ページが本体に無い** | 5社中4社が本体に料金ページ。Schoo・AirCourse・learningBOX・インソースLeafは金額まで全公開。インソースLeafは1ID 500円・初期10万円とmanebiと同構造を公開しており、**非公開に競争優位はない** |
| P1 | **機能一覧ページが無い** | 全5社が保有（learningBOXは18下層）。「LMS 機能」「eラーニングシステム 比較」検討層の土俵に乗れていない |
| P1 | **BOFU向けCTA導線が無い** | Schoo「料金表をダウンロード」、Smart Boarding「この見積もりプランで相談する」等、価格を知りたい意図に直接応えるCTAを全ページ反復 |
| P1 | **事例が探せない・成果数値が薄い** | SmartHRは業種×規模×課題×機能×地域の5軸フィルタ。競合事例は「受講率65%→9割」型の数値見出し。導入6,900社の資産が未活用 |
| P2 | 課題別・階層別・業界別LPが無い | インソースは階層×業界×テーマのマトリクスで数千ページ。Schooは研修パッケージ30種超 |
| P2 | セキュリティ専用ページが無い | 情シス稟議の必須要件。競合は認証番号まで明記 |
| P2 | 比較コンテンツを自社ドメインに持たない | AirCourseは「10社比較」記事群、SBは「徹底比較表つき資料」でリード化 |
| P2 | 不安払拭マイクロコピー・反論処理FAQの不在 | Schooは「決裁者にどう説明すればいい？」FAQ＋助成金案内まで実装 |
| P3 | 信頼要素の数値化・出典表記が弱い | 競合はNo.1・継続率に必ず調査出典と時点を付記（景表法対応の観点でも必須） |
| P3 | グロナビが検討プロセス非対応 | 「料金」「機能」「選ばれる理由」というBOFU 3大導線がナビに無い |

### manebiの勝ち筋（競合実査から逆算した強み）

- **価格構造**：1ID 500円〜・使わない月は調整可 — 公開すれば AirCourse型の透明性訴求で戦える
- **無料デモの即時性**：申込後最速30分でID発行し実環境を触れる。競合は「日程調整→営業同席デモ」が主流で、**この即時性はCTA文言として突き抜ける**（§07）
- **AI機能の先行**：競合のAI訴求は発展途上。「manebi＝AIに強い」の独立ページで先行優位を取れる
- **導入6,900社×継続率98.8%**：数はあるのに見せ方の問題。事例DB化＋出典付きバッジで即戦力化

## 04 情報設計（IA）・新サイトマップ

年明けの制作会社壁打ちで作成した「松プラン」サイトマップをベースに、競合分析の結果（BOFU 3導線のナビ昇格）と受講者導線を加えて再構成する。

### 新グローバルナビ（案）

```text
manebi（ロゴ）
├ サービス            ▾ 【経営・組織】Wonder AI / 企業リブランディング / 人事評価(グループ会社Prime↗)
│                      【教育】eラーニング / 集合研修　【業界向け】派遣・警備・建設
│                      ※DXコンサルは撤去（v1.6）
├ 機能               ▾ 機能一覧 / AI機能(特化P) / セキュリティ / システム連携
├ 料金               … 料金・プラン＋見積シミュレーター統合（simulation-cp移植）
├ 教材・研修          ▾ 🖥 eラーニング教材（教材・講座一覧＝owned／人気講座）
│                      👥 集合研修（ラインナップ一覧(T14)／講師派遣／組み合わせ事例）
│                      テーマから探す（新入社員/管理職/ハラスメント/コンプラ…＝形態横断ハブ）※CMS量産
├ 導入事例            … 業界×規模×課題フィルタ
├ お役立ち            ▾ 資料ダウンロード / コラム / セミナー / FAQ
│
├ 受講者の方はこちら（ログイン）   ← 3ヶ月960クリックの受け皿
└ [資料DL] [無料デモ]  ← ヘッダー固定CTA 2本
```

緑＝新設、紫＝CMSテンプレで量産するページ群。「お役立ち記事」は「コラム」へ表記変更（他の表記も §05 各テンプレで定義）。

### 設計の根拠

- **「サービス」と「研修ラインナップ」の役割重複を解消**：サービス＝提供形態（何で学ぶか）、研修テーマ＝中身（何を学ぶか）に再定義。研修テーマは現在の4メニューから**階層別×テーマ別で20本規模に拡張**し、SEO受け皿を兼ねる（§06）
- **BOFU 3導線（料金・機能・事例）をナビ第一階層に**：検討プロセス対応（AirCourse型）
- **業界特化（派遣・警備・建設）をフッターからナビへ昇格**：外部サイトへの分散も将来的に集約検討（未決事項）
- **フッターはペルソナ別3ブロック再編**（SmartHR型）：導入検討中の方／ご利用中の方／パートナー

### 流入元別の情報連続性マップ（v1.4）

| 流入元 | 直前に見ている情報・期待 | 受けページ／施策 |
| --- | --- | --- |
| **比較サイト**（BOXIL・ITトレンド・アイミツ・ミツモア等） | 各社の料金・機能・口コミを横並びで見比べた状態。「本体サイトに料金が無い」と情報が後退し離脱 | T2料金（金額公開）・T3機能・T13比較・数字実績。比較サイト掲載スペックと本体の記載を**定期突合する運用**（比較サイト側の掲載情報もマーケが台帳管理） |
| **コーポレートサイト**（/corp/service/manebi/ 等） | 会社・サービス概要を見て「機能・料金・活用事例」CTAをクリック。**現状、遷移先に料金プランが無い** | corp側の全リンク文言×遷移先ページを棚卸しし、文言が予告する情報（料金→/price/、機能→/function/、事例→/case/）へ差し替え。Phase 1タスク |
| **広告LP**（/std_03h等） | 単一訴求のLPで興味喚起済み。詳細（料金・教材・事例）を確かめたい | LP→本体（料金・事例・教材）への回遊導線を明示。キャンペーン枠の試算CTAは**シミュレーターへ直リンク**（Phase 0クイックウィン） |
| **検索（コラム着地）** | 情報収集段階。売り込みへの耐性が低い | T9の段階的CTA（テキスト→バナー→記事末）＋ピラー誘導で検討段階を引き上げ |
| **指名検索（受講者）** | ログインしたいだけ | ヘッダー「受講者ログイン」＋ /login/ 案内ページで即退避 |

あわせて全主要ページに**「こんな企業さまに向いています」適合ガイドブロック**を設ける（利用実績ベース：業種比率・規模・利用用途から「製造業で新人教育を内製化したい」等の適合パターンを明示。向かないケースにも軽く触れて誠実さを担保＝「不信」対応・失敗あるあるとの整合）。掲載先：T1・T2・T6・T7。

### 既存URLの扱い（憲法）

既存URL・月間3.7万セッションは無傷のまま増築する（AI集客エンジン側の運用原則と同一）。**URL変更は原則行わず**、やむを得ない場合は301リダイレクト計画を作成し、エンジン側（カニバリ判定・内部リンク）へ事前通知する。§09参照。

## 09 AI集客エンジン互換要件

島崎さん作のAI集客エンジン（200_AI集客エンジン）は講座LP・記事・FAQ・構造化データをWordPress下書きとして量産する。リニューアル後のサイトはこの**量産物の受け皿**として設計する。

- **テンプレ互換**：エンジンが生成する講座LP・記事が、T6/T8/T9テンプレに手直しなしで流し込める入稿仕様（見出し構造・FAQブロック・CTAブロック・JSON-LD）を共同定義する。CTA・FAQはWordPressブロックパターン化し、エンジン側は中身だけ生成
- **既存資産の保護**：既存URL・月間3.7万セッションは無傷（エンジン側の運用原則と共通）。リニューアルでURL変更が必要な場合は301計画を作り、エンジンのカニバリ判定・内部リンクマップへ事前反映
- **公開フローの尊重**：エンジンの「下書き強制・公開ボタンは人間」の原則はリニューアル後も不変。サイト側で公開系の自動化は作らない
- **受講者の声の素材化**：声データをエンジンに渡す場合は同意済み＋PIIマスキング済みのみ（エンジン側憲法のVoice入力制限に準拠）
- **リライト運用の接続**（§06）：順位下落検知→リライトキュー起票をエンジンのルーティンに載せる案を島崎さんと協議
